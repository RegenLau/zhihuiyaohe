一、需求背景

1.1 现状问题

  • 智慧药盒需要进入基层医疗和家庭场景试点，但目前缺少医药师可操作的 PC 后台。
  • 在未接通医院 HIS、审方系统等接口前，处方和用药计划需要由医药师人工维护。
  • 患者服药任务、药盒开关记录、提醒结果如果无法在后台查看，就无法形成管理闭环。
  • 现场应用需要明确完整功能链路，而不是只依赖单点硬件能力。

1.2 为什么现在做

项目需要在基层医疗机构和患者家庭之间建立一套可持续运行的用药管理链路。医药师后台是业务闭环的中心：所有患者、计划、设备和任务数据都需要先在后台形成，并可被小程序端和药盒端持续使用。

1.3 产品定位

当前阶段不替代完整医院信息系统，而是建设一套面向基层慢病用药管理的轻量后台。首次建档采用分步向导，确保患者信息、用药计划、药盒绑定和任务生成不遗漏；后续复诊和日常维护仍保留独立模块，方便单独调整用药计划、药盒和提醒消息。

二、需求目标

目标类型描述衡量指标目标值
业务闭环目标 医药师可通过建档向导完整完成新增患者、创建用药计划、绑定药盒、生成任务，并可在独立模块中进行后续维护。 核心流程可完成率 100%
业务目标 支撑基层医药师管理 10 到 20 名老年慢病患者。 单医药师可管理患者数量 不少于 20 人
数据目标 沉淀患者、药品、计划、任务、药盒、消息的数据结构，为后续真实接口和数据库做准备。 核心实体覆盖率 覆盖 P0 模块
体验目标 后台操作像常规管理系统，医药师无需理解底层设备技术即可完成配置。 新增患者并创建计划耗时 标准录入场景下小于 3 分钟

三、用户与使用场景

3.1 典型用户

医药师

医生和药师在系统中合并为同一业务角色。该角色负责患者诊疗信息、基础疾病、处方调整、用药计划录入、处方核对、药盒绑定、服药任务查看、复诊提醒和高风险对话复核。

管理员

负责医药师账号、药盒设备、业务数据和基础字典维护。关注系统环境是否稳定。

3.2 核心用户旅程

阶段用户触点用户行为痛点 / 风险产品机会点
患者建档 医药师后台 录入患者基础信息、疾病信息、子女联系方式。 没有 HIS 接口时，患者信息只能手动维护；身份证号涉及隐私和合规。 提供清晰表单；身份证号设为可选；显示知情同意状态。
首次开方 用药计划页面 根据处方手动录入药品、剂量、频次、服药时间。 处方来源可能是纸质照片、HIS 截图或人工输入。 支持处方附件上传和药品明细手动维护。
设备绑定 药盒绑定页面 选择药盒 SN，绑定患者，生成或记录小程序绑定状态。 患者和子女不一定同时在现场；配网流程可能不稳定。 后台只负责绑定关系和状态展示；小程序端负责配网引导。
日常管理 任务与看板 查看患者每日服药任务完成情况、漏服情况和药盒开关记录。 如果数据只存在硬件侧，医药师无法评估依从性。 按患者聚合任务、完成率、异常记录。
复诊调整 计划和提醒页面 停用旧计划，新增或修改新计划，创建复诊提醒。 老年慢病患者复诊后常有换药、停药、加药。 计划支持版本和启停；旧计划可归档，新计划可生效。

五、详细方案

5.1 医药师工作台

页面目标

医药师登录后第一屏看到当前管理范围内的患者和任务风险，快速进入待处理患者。

核心信息

  • 统计卡片：患者总数、已绑定药盒数、今日服药任务、今日漏服人数、待复诊人数。
  • 风险列表：连续漏服、未绑定药盒、药盒离线、复诊临近。
  • 快捷入口：新增患者、创建用药计划、绑定药盒、创建提醒。

SaiAdmin 落地

建议路径：frontend/src/views/plugin/t2/dashboard/index.vue。使用现有卡片和表格组件实现。

5.2 患者管理

列表字段

字段说明
患者姓名必填；支持按姓名搜索。
性别 / 年龄基础展示字段。
手机号用于联系和小程序绑定。
身份证号选填；为未来医院系统对接预留。
基础疾病多选或文本；如高血压、糖尿病、帕金森等。
实名状态未实名 / 已登记 / 已核验；当前可由后台维护展示。
知情同意待确认 / 已同意 / 已撤回；状态来自小程序端确认结果，后台不代替患者确认。
药盒状态未绑定 / 已绑定 / 离线。
子女绑定未绑定 / 已绑定；可查看绑定子女。

操作规则

  • 新增患者时走建档向导，姓名、手机号、性别、年龄为必填；身份证号为选填。
  • 删除患者时，如果存在生效中的用药计划或绑定药盒，默认提示先停用计划或解绑药盒。
  • 患者详情页应聚合展示：基本信息、用药计划、服药任务、药盒、子女账号和提醒记录。
  • 知情同意由患者或家属在小程序端阅读并点击确认；后台只展示确认状态、协议版本和确认时间。

首次建档向导

步骤内容规则
1. 患者信息姓名、手机号、性别、年龄、身份证号、地址。保存患者主档案。
2. 诊疗信息基础疾病、诊疗备注、子女联系人。子女信息可后续补充。
3. 用药计划处方来源、药品明细、频次、疗程、复诊提醒。保存后生成计划草稿或直接生效。
4. 设备绑定药盒 SN、小程序绑定二维码、知情同意状态。知情同意状态为“待患者在小程序确认”。
5. 确认建档汇总校验并生成服药任务。缺少药盒时允许先建档，任务下发状态标记为待绑定。

SaiAdmin 落地

建议路径：frontend/src/views/plugin/t2/patient/index.vue，弹窗模块放在 patient/modules。

5.3 用药计划管理

业务规则

  • 一个患者可拥有多条历史用药计划，但同一药品同一时段不应存在冲突的生效计划。
  • 复诊后可停用旧计划，复制旧计划生成新计划，再进行换药、停药、加药。
  • 计划保存后生成每日服药任务；任务用于小程序打卡和药盒提醒。
  • 复诊提醒可按药品数量、用法用量、疗程天数推算，也允许医药师手动设置。

药品明细字段

字段说明
药品名称必填；当前可手动输入。
规格如 5mg*28 片。
单次剂量如 1 片、2 粒。
服药频次每日一次、每日两次、每日三次、按需。
服药时段早餐后、午餐后、晚餐后、睡前等。
开始 / 结束日期用于生成任务和推算复诊。
状态草稿、已生效、已停用、已完成。

SaiAdmin 落地

建议路径：frontend/src/views/plugin/t2/medication-plan/index.vue。计划编辑建议使用抽屉或全屏表单，药品明细用可增删表格。

5.4 处方管理

当前不强依赖 OCR，处方先作为用药计划的来源附件，便于业务追溯和后续识别能力接入。

  • 支持上传纸质处方照片。
  • 支持上传 HIS 或审方软件截图。
  • 一个用药计划可关联多张处方附件。
  • 附件字段：文件名、类型、上传人、上传时间、关联患者、关联计划。

建议路径：frontend/src/views/plugin/t2/prescription/index.vue，也可先内嵌在用药计划编辑页。

5.5 设备管理

页面目标

后台负责维护药盒和患者的绑定关系，展示药盒状态。配网本身由小程序端引导，后台不直接承接 WiFi 输入。

列表字段

  • 药盒 SN、设备名称、在线状态、电量、最近上报时间、绑定患者、绑定时间。
  • 开关记录：时间、格口或开关编号、动作、上报结果。
  • 下发记录：计划 ID、下发时间、下发状态、失败原因。

操作规则

  • 绑定药盒时必须选择患者。
  • 同一药盒同一时间只能绑定一个患者。
  • 解绑时保留历史任务和开关记录，不物理删除。

建议路径：frontend/src/views/plugin/t2/device/index.vue。

5.6 服药任务完成情况

状态定义

状态说明
待服药计划生成但尚未到服药时间，或到点后未收到完成。
已完成患者小程序打卡或药盒开关记录匹配成功。
漏服超过允许时间窗口仍未完成。
设备异常计划下发失败、药盒离线或开关上报异常。
已取消计划停用后，未来任务取消。

查看维度

  • 按患者查看：展示某个患者的今日任务和历史完成率。
  • 按日期查看：展示医药师管理范围内当天所有任务。
  • 按异常查看：筛选漏服、连续漏服、设备异常。

建议路径：frontend/src/views/plugin/t2/medication-task/index.vue。

5.7 复诊提醒与子女提醒

提醒类型

  • 复诊提醒：根据用药计划推算或医药师手动创建，可下发到药盒语音提醒和小程序消息中心。
  • 子女提醒：当患者近期服药完成情况差时，医药师可生成提醒给子女端消息中心。
  • 系统提醒：药盒离线、计划下发失败等系统生成消息。

约束

  • 当前小程序不一定具备主动外部推送能力，因此以“消息中心”和后台记录为主。
  • 短信、公众号服务号、APP push 作为后续通知渠道扩展。

建议路径：frontend/src/views/plugin/t2/message/index.vue。

5.8 对话记录

页面目标

医药师可以查看患者通过药盒发起的语音问答记录，追踪知识库命中、系统答复、风险等级和复核处理结果。

核心字段

字段说明
对话时间患者发起语音咨询的时间。
患者 / 药盒关联患者、药盒 SN 和家庭场景。
提问内容语音识别后的文本，可保留原始语音文件地址。
问题类型服药方法、药品相互作用、不良反应、复诊咨询等。
知识库命中命中的知识库、规则或问答条目。
答复摘要系统返回给患者的核心答复。
处理状态已答复、待复核、转人工。
医药师复核意见医药师对答复是否合规、是否需要随访的判断。

业务规则

  • 涉及胸闷、严重不适、疑似不良反应的问题，应标记为高风险并转人工处理。
  • 涉及药品相互作用的问题，应展示知识库来源，便于医药师复核。
  • 复核后可生成子女提醒、复诊提醒或随访记录。

建议路径：frontend/src/views/plugin/t2/conversation/index.vue。

5.9 系统设置

页面目标

后台维护小程序端展示的知情同意书内容、版本和启用状态。患者或家属在小程序端阅读并点击确认，后台只记录确认状态和协议版本。

知情同意书配置字段

字段说明
协议名称例如“智慧药盒服务知情同意书”。
协议版本每次发布新内容生成新版本，历史版本不可覆盖。
适用端患者端、子女端或两者同时适用。
协议摘要小程序端列表或弹窗中的简短说明。
协议正文完整知情同意内容，包含服务目的、信息采集、风险提示和授权确认。
启用状态启用、停用、归档。

业务规则

  • 后台可以编辑和发布知情同意书内容，但不能替患者或家属确认。
  • 小程序绑定药盒或首次进入服务前，应展示当前启用版本并要求点击确认。
  • 患者确认记录需保存协议版本、确认人、确认时间、确认端和关联患者。
  • 协议新版本发布后，是否要求老用户重新确认应由系统设置控制。

建议路径：frontend/src/views/plugin/t2/settings/index.vue。

    C2 --> E[添加用药计划]
    C1 -- 否 --> D{是否需要调整用药计划}
    D -- 是 --> F[复诊后复制或修改计划]
    D -- 否 --> J
    E --> G[录入药品明细]
    F --> G
    G --> H[上传处方照片或截图]
    H --> I[保存并生成服药任务]
    I --> J[绑定药盒]
    J --> K[记录小程序和子女绑定状态]
    K --> K1[患者或家属在小程序确认知情同意]
    K1 --> L[药盒接收计划并提醒]
    L --> M[患者服药或小程序打卡]
    L --> T[患者通过药盒发起语音咨询]
    T --> U[系统生成对话记录]
    U --> V{是否高风险或需复核}
    V -- 是 --> W[医药师复核或转人工]
    V -- 否 --> N
    M --> N[后台查看任务完成情况]
    N --> O{是否异常}
    O -- 否 --> P[持续观察]
    O -- 漏服或依从性差 --> Q[创建子女提醒]
    O -- 药快吃完或需复诊 --> R[创建复诊提醒]
    Q --> S[小程序消息中心查看]
    R --> S

七、异常与边界处理

场景处理方式提示文案建议
新增患者手机号重复提示用户选择已有患者或继续创建新患者。该手机号已存在患者，请检查后再保存。
患者存在生效计划时删除阻止删除，要求先停用计划和解绑药盒。该患者存在生效中的用药计划，暂不能删除。
用药计划时间冲突提示冲突药品和时间，允许保存草稿，不允许直接生效。当前计划与已有计划存在服药时间冲突。
药盒已绑定其他患者阻止重复绑定。该药盒已绑定患者，请先解绑后再操作。
药盒离线允许保存计划，但下发状态标记为待下发或失败。药盒当前离线，计划将在设备在线后重试下发。
处方附件上传失败保留表单草稿，允许重新上传。附件上传失败，其他信息已暂存。
无子女绑定允许创建患者和计划，但子女提醒不可发送。当前患者未绑定子女账号，暂不能发送子女提醒。
小程序无法外部推送消息进入消息中心，后台展示未读状态。消息已创建，用户登录小程序后可查看。
